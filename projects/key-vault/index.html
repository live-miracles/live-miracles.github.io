Add every stream destination for a live event, and see in plain words whether each one is working.

Key Vault is a web app for media teams who send a live stream to many places at once: YouTube, Facebook, Instagram, TV channels and other third parties. It replaces the shared spreadsheet of stream keys with a guided form that stops wrong links, and it shows the live status of every destination, so nobody has to ask "is it going out?" in a chat.

Why it exists

Stream keys used to travel in a Google Sheet. Then a key went into the address box (or the other way round), the backup column held the main link, and nobody knew a link was wrong until the stream failed on air. When a channel said it was not receiving anything, the media team could not see which output was down, or why.

  • Wrong links cannot be saved. The form asks only for what each platform needs, cuts a pasted full address down to the key, and checks the result. The server checks again, so nothing that skips the form can store a bad link.
  • Every destination shows its real state. The streaming server, bunryu, reports each output once a minute. A card shows Live, Unstable, Problem, Not sending or Not set up yet. Nobody sets a colour by hand.
  • It says what to try. A red card says, in plain words, what is probably wrong ("The platform did not accept the stream key. Get a fresh key from the platform and update it here.") and who to tell. When the input is not arriving, it says so, and nobody wastes time chasing the platform.
  • Changes are visible. A replaced link stays Not set up yet until the streaming server has it, and each card records who last changed it and when.
  • Access follows the work. Admins have every event. Everyone else is an editor or a viewer of an event, and can be limited to a single input, such as one language. The server decides what each person may do.
  • Installs like an app. Chrome, Edge and phones can add it to the desktop or home screen.

Try it

Run the demo on your own machine. It uses made-up events and statuses, so it needs no account:

git clone https://github.com/live-miracles/key-vault.git
cd key-vault
npm install
npm run dev        # http://localhost:2837

Use Add destination to see the guided form. Everything the demo does runs the same operations as the real server.

Install it as an app

Open the site in Chrome or Edge and click the install icon in the address bar. Key Vault then opens in its own window, with its own icon, like any other app. Phones can use Install app or Add to Home Screen. See Install Key Vault as an app. It always shows live data, so it is not an offline tool.

How it fits together

Browser → Vercel static site → Supabase Auth (Google)
                            └→ Edge Function `api` → Postgres
bunryu ──every minute──► Edge Function `ingest` → Postgres

The browser never reads the database directly: every table has row-level security with no policy. Every call goes to the api function, which decides what the signed-in user may do, checks the destination against the platform rules (the same module the form uses) and only then uses the service role. The data it returns says what the user may do with each item, so the screens hold no rules of their own.

bunryu sends a hash of each destination address, never the address. Key Vault hashes its own main and backup addresses and matches them, so a destination shows as running, warning, error or configured-but-stopped without anyone setting a colour. Stream keys never go to bunryu's heartbeat or into a URL. The details are in The bunryu link.

It runs on Vercel (the site) and Supabase (sign-in, database and two Edge Functions), and fits their free plans.

Roles

  • Editor: can add and edit destinations, and can be limited to one input.
  • Viewer: can only view destinations, and can be limited to one input.
  • Admin: has every event and can do everything: create, rename, delete and restore events, manage inputs, share events, and add or remove other admins.
  • Owner: an admin named in KEY_VAULT_OWNER_EMAILS. Owners cannot be added or removed in the app, and also open the bunryu settings and read bunryu's technical report.

Editor and viewer are given per event, in Share. Admin is not: admins are listed once for the whole app, in the Admins dialog (bottom right), where the owners are shown as fixed. Share lists them too, read only.

  • Any admin can add and remove the other admins in that dialog, except themselves.
  • A deleted event is kept for 30 days, and an admin brings it back from History (bottom right, admins only).
  • History (admins only) keeps every change of the last 30 days: who, when, and the row before and after. An admin can open an event as it was right after any change, see every difference from now, and restore the whole event to it. A restore is itself recorded, so it can be undone. See ADR 5.
