Prerequisites: Node.js 22+ plus curl, unzip, tar, and xz-utils.

1. Install dependencies and local media binaries:

npm install
npm run dev-install   # downloads SRS and pinned FFmpeg into ./objs

The relay lives in the sibling ../goryu repo in development (and in live-miracles/goryu releases for production installs). Rerunning npm run dev-install refreshes that repo when it has no local changes and rebuilds ./objs/goryu.

To use a local SRS binary:

SRS_LOCAL_BIN=./build/srs npm run dev-install

2. Start SRS (terminal 1):

npm run srs           # runs ./objs/srs -c srs.conf in the foreground

3. Start Goryu (terminal 2):

npm run goryu          # runs the ./objs/goryu binary built by dev-install
npm run goryu:update   # pulls the latest ../goryu source and rebuilds ./objs/goryu

The relay also exposes a local HTTP status endpoint on the default status_port (127.0.0.1:8081) in development. The dashboard backend polls that endpoint to show the top-level relay health and the per-pipeline bonded-input status.

4. Start the app (terminal 3):

npm run dev           # tsx watch + tsc watch + tailwind watch

A fresh database is seeded with the dashboard_password in bunryu.json, which the repo ships as change-me for development only (the installer and the Docker image never use that file). The app has no built-in default: if you empty or delete that line it refuses to start on a fresh database, unless BUNRYU_DASHBOARD_PASSWORD is set. Later starts use the hash stored in the database.

Tests

npm test              # unit and integration tests
npm run typecheck
npm run lint          # ESLint: unhandled promises, dead code
npm run format:check

test/malformedInput.test.js feeds seeded random mutations of ss output, destination URLs, names, the relay config and the relay /status JSON to their parsers and asserts they never throw, hang or return a malformed value. A failure prints the seed and input; turn it into a regression test next to the parser's own. Add a parser that reads text from outside the process (a new ss, FFmpeg, SRS or relay output) to that file.

scripts/test-stack.sh starts an isolated local stack (its own SRS, control plane and fresh database, with a fake output FFmpeg) that does not touch a developer's own npm run dev. It is documented in skills/run-bunryu/SKILL.md.
